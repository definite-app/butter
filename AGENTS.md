## Project Summary
Butter is a macOS Tauri app that embeds xterm.js terminals in a full-screen UI with an Arc-style sidebar for session organization (tags, presets, filters). Frontend is Solid.js + TypeScript; backend is Rust + Tauri v2 with a PTY layer (portable-pty) that streams terminal I/O to the UI.

## Repo Layout
- `src/` — Solid.js frontend
- `src-tauri/` — Rust backend and Tauri config
- `src-tauri/src/` — Core Rust modules (`lib.rs`, `pty.rs`, agent API/db)

## Common Commands
```bash
npm install
npm run dev
npm run build
cd src-tauri && cargo tauri dev
cd src-tauri && cargo tauri build --bundles app
```

## Development Notes
- Terminals are rendered via `xterm.js` in the webview.
- PTY lifecycle is handled by Tauri commands (`pty_create`, `pty_write`, `pty_resize`, `pty_close`) and `pty-data` events.
- Presets, tags, and UI state are stored in localStorage.
- The main window is full-screen; the sidebar is part of the web UI (not a separate window).
- Team Mode is a separate Slack-like frontend mode backed by the existing Rust/Tauri SQLite database; it stores users, channels, messages, and pins, and uses `butter-cli` for agent communication/configuration.

## Code Style
- TypeScript: strict, no `any`, no unused variables.
- Rust: standard Tauri patterns, snake_case.
- Solid.js: use `createSignal`/`createEffect` for reactivity.

## Building and Installing
Mike runs Butter nearly 24/7, often with Claude/Codex sessions inside it. Quitting Butter ends every terminal. The reopen picker restores them on relaunch, and agents resume their conversations, but a turn that's running gets cut off.

- **CI** (`.github/workflows/build-macos.yml`) builds an ad-hoc-signed `Butter.app` for every PR and every push to `main` and uploads it as the `Butter-macos-arm64.zip` artifact, which unzips straight to `Butter.app`. It runs no tests and installs nothing.
- **Install with `scripts/install-app.sh`**, never by hand. It builds, checks the bundle id, waits until no Claude session is working (`--wait`), quits Butter cleanly, saves the old app to `~/Butter.app.bak-<timestamp>` (keeps 3), installs and reopens it. It is safe to run from a terminal inside Butter: the swap runs in a detached process and logs to `$TMPDIR/butter-install-prod.log`.
  - `--dev`: Butter Dev (`com.butter.app.dev`, data in `~/.butter-dev`). Use it to try changes without touching the Butter you work in.
  - `--ci [RUN_ID]`: install the latest green `main` CI build (or that run) instead of building locally.
  - `--skip-build`, `--dry-run`, `--force`, `--rollback` (swap the newest backup back in).
- **Build from `main` (or a branch based on it) before installing into `/Applications/Butter.app`.** A build from an older branch silently drops fixes that are already merged.
- Agents: build and test freely while Butter is running. Don't quit, install or relaunch Butter unless Mike asks; say when an install is ready and give the command.
- `butter-cli` and `butter-browser` are generated by the app (`install_cli_shim` in `src-tauri/src/browser.rs`) and rewritten to `~/.butter/bin` (Butter Dev: `~/.butter-dev/bin`) on every launch. There is no separate CLI build.

Before installing, run:
```bash
npx tsc -b
npm run test:composer
(cd src-tauri && cargo test --lib)
```

## Permissions and signing
- macOS keys permission grants (Screen Recording, Microphone, Full Disk Access, folders, Automation) to the app's designated requirement. An ad-hoc build's requirement is its code hash (`codesign -dr -` prints `cdhash H"…"`), so every build looked like a new app and lost its grants.
- `scripts/install-app.sh` re-signs every bundle it installs (local build, `--ci`, `--skip-build`, `--rollback`, also on `--dry-run`) with `scripts/sign-app.sh`: `$BUTTER_SIGN_IDENTITY` (name or SHA-1; `-` forces ad-hoc), else the first "Developer ID Application", else the first "Apple Development" identity in the keychain. It signs nested code first, then the bundle with `src-tauri/entitlements.plist`, and fails unless `codesign --verify --strict` passes and the requirement no longer pins a cdhash. With no identity it signs ad-hoc and warns. No hardened runtime locally; Developer ID + notarization in CI will need `--options runtime` and `com.apple.security.device.audio-input`.
- The first stable-signed install can leave old toggles on that no longer apply. Fix with "Reset stale grants…" in the Permissions view (`tccutil reset All <bundle id>`).
- **Permissions view** (Cmd+K "Permissions"; `src/features/permissions/`, backend `src-tauri/src/permissions.rs`): Butter's own (Notifications, Screen Recording, Microphone), the ones charged to Butter for terminal commands (Full Disk Access, Desktop/Documents/Downloads, Automation), and ButterRec's (from its daemon's `status` over `~/.butter/rec.sock`). Grant shows the system prompt where macOS has one and it hasn't been answered, else opens the exact System Settings pane. Rows re-check when the window regains focus. Full Disk Access is detected by opening the user's `TCC.db` (no prompt); folder and Automation access can't be checked without prompting.
- The view opens by itself once on first launch, and once when the designated requirement differs from the one in `<butter home>/signing.json` while one of Butter's own permissions isn't granted.
- WebKit keeps a login-keychain item, "butter WebCrypto Master Key", for pages that store crypto keys. Its access list trusts the build that made it, so after a signature change macOS may ask once to let Butter use it; choose Always Allow. Butter itself stores nothing in the keychain.

## Composer Dock (Cmd+I)
- `src/features/composer/` (UI + pure logic in `logic.ts`, tests in `scripts/composer-logic.test.ts`, run `npm run test:composer`); backend in `src-tauri/src/composer.rs`.
- Drafts are files under the flavor data dir (`~/.butter/drafts`, `~/.butter-dev/drafts`); sent drafts move to `drafts/sent/` and `drafts/history.jsonl`.
- Send = one bracketed paste via xterm `paste()`, then a separate `\r` after a short delay (`ENTER_DELAY_MS`).
- Optional TypeSafe Jev reranking: `[typesafe] api_key = "..."` in `config.toml` (or env `TYPESAFE_API_KEY`); `timeout_ms` (default 300). The key never reaches the webview.

## Routines
- Scheduled check-ins for 1thread. `butter-cli routine create --in 2w "<prompt>"` (or `--at YYYY-MM-DD [HH:MM]`; date-only means 9:00 local) saves a routine in the `routines` table; `list`, `snooze`, `cancel` manage it. Backend in `src-tauri/src/routine.rs`, HTTP routes `/routine/:session/*`.
- While Butter runs, the 1thread model checks once a minute (first check 15s after launch, which also catches routines missed while Butter was closed). A due routine starts a new agent looped into the conversation it came from, with the same preset and folder, the conversation so far, a pointer to the earlier agent's transcript, and the routine's prompt. From a plain terminal it starts a new thread in that folder.
- The woken agent can run `butter-cli routine snooze --in 1w` (no id needed) to check again later.
- Agents learn the commands from the `butter-cli` skill (`.claude/skills/butter-cli/`). Butter copies it into `~/.claude/skills/` and `~/.codex/skills/` on every launch (`src-tauri/src/agent_skill.rs`), unless the user has their own copy there (a SKILL.md without Butter's marker line).

## Browser profiles, apps and browser.toml
- `<config dir>/browser.toml` (`~/.config/butter/browser.toml`, Butter Dev: `~/.config/butter-dev/browser.toml`) holds browser profiles, pinned web apps and URL palette commands. It's separate from `config.toml` because saving settings from the UI rewrites that file and drops sections it doesn't know. Butter creates it with commented examples on first launch and never overwrites it. It's re-read when its mtime changes: when Cmd+K opens, when the window gets focus, and when a pane opens. Code: `src-tauri/src/browser_config.rs` (parsing, edits), `src/features/browser/logic.ts` (URL resolution, match filtering).
  ```toml
  [[profile]]
  id = "work"            # letters, digits, - and _
  name = "Work"
  color = "#7aa2f7"      # optional hex color

  [[app]]                # pinned web app: sidebar "Apps" section and Cmd+K "Open Gmail"
  id = "gmail"
  name = "Gmail"
  url = "https://mail.google.com/mail/u/0/"
  profile = "work"       # optional, default "default"

  [[command]]            # Cmd+K item that opens a URL
  name = "Gmail: Search"
  url = "#search/{query}"            # absolute, or relative to the current page
  match = "https://mail.google.com/*" # optional Chrome match pattern
  ```
- **Profiles.** A `default` profile always exists. Every profile, `default` included, gets its own WebKit data store from a hash of its id (`data_store_identifier`), never WebKit's default store, which Butter's UI uses. A pane starts on its preset's `browser_profile` (config.toml, also in the preset editor), or on an app's `profile`, and keeps it until switched from the footer chip; switching recreates the webview and reloads the page. Unknown ids mean `default`. The terminal's folder plays no part. URL history (localStorage `butter.browser-url-history.v1`) is keyed by profile id. Cmd+K "Browser Profiles" (or "Manage profiles…" in the chip) lists profiles with what uses them, open panes and the sites with data (`WKWebsiteDataStore fetchDataRecordsOfTypes:`), and can remove one site's data, clear a profile, create one or rename/recolor one. Create and rename edit browser.toml with `toml_edit`, keeping comments.
- **Apps.** An app is a browser not tied to a terminal, session id `app:<id>` (`pty_create` rejects that prefix; apps never enter the sessions store, DB or reopen picker). It shows full-window (Cmd+Shift+F or the toolbar button puts it beside the sidebar instead), and switching to a terminal or another app hides its webview without closing it.
- **Commands.** `{query}` makes the palette ask for text first (Enter or Tab on the item), URL-encoded into the url. A relative url resolves against the active browser's page; a fragment-only change is handed to the page (`location.href`) instead of reloading. Commands with `match` show only while the active browser (the app on screen, else the terminal's open pane) is on a matching page, first, under the page's host. Commands without `match` are bookmarks: they open in the active pane, or open the terminal's pane.
- **Shortcuts in pages.** The initialization script catches Cmd+K, Cmd+Shift+K and Cmd+Shift+F in the window capture phase, before the page's handlers, and posts them to `/browser/shortcut`. Butter's webview takes focus for the palettes and the page gets focus back when the palette closes. While any palette or menu is open the native webviews are hidden (`anyOverlayOpen`) and a dimmed JPEG snapshot (`browser_suspend`) stands in for each.
- **Inbox Keys in Cmd+K.** On a Gmail page Cmd+K lists Inbox Keys' commands under "Inbox Keys": Butter evaluates a page-world script that sends `butter:inboxkeys-request` DOM events, and the shim in the userscript's isolated world answers. Inbox Keys' own palette moved to Cmd+J (see `vendor/inbox-keys/SOURCE.md`).

## Userscripts (browser pane)
- Tampermonkey-style scripts for the browser pane live in `~/.config/butter/userscripts/` (Butter Dev: `~/.config/butter-dev/userscripts/`). Every `*.js` file there with a header is loaded, in name order, when a browser pane is created, and again when Butter's reload button or a navigation from Butter runs. A reload from inside the page doesn't re-read the folder. Code: `src-tauri/src/userscripts.rs` (parsing, matching, installing) and `replace_userscripts` in `src-tauri/src/browser.rs` (injection).
- Header:
  ```js
  // ==UserScript==
  // @name         My script
  // @match        https://mail.google.com/*
  // @run-at       document-idle
  // @noframes
  // ==/UserScript==
  ```
  `@match` takes Chrome match patterns and can repeat. A script without `@match` is skipped, and `@include`/`@exclude` are ignored. `@run-at` is `document-start`, `document-end` or `document-idle` (the default). `@noframes` keeps the script out of iframes. `@inject-into page` runs it in the page's own JavaScript world instead of an isolated one.
- By default each script runs in its own isolated `WKContentWorld`, like a Chrome content script. It shares the DOM with the page but not its globals, and the page's CSP doesn't block it. WebKit 26 enforces Trusted Types, so on Gmail `innerHTML` throws in the page world but works in an isolated world. Scripts get `GM_addStyle(css)` and `GM_info`. Their console output goes to Web Inspector, not to `butter-browser console`.
- **Inbox Keys** (Gmail palette on Cmd+J, hotkeys, split inbox, account switching; MIT, vendored in `src-tauri/vendor/inbox-keys/`, source commit in `SOURCE.md`) is installed on every launch as `inbox-keys.user.js` (Gmail), `inbox-keys-calendar.user.js` (Google Calendar) and `inbox-keys-account-bridge.user.js` (runs in the page world to read the account list). `butter-chrome-shim.js` stands in for `chrome.storage` (backed by the page's localStorage) and `chrome.runtime`. Settings are in the in-Gmail settings modal. The extension's popup and options page aren't included.
- Butter rewrites those files on every launch while they contain the line `// Installed by Butter, which rewrites this file on every launch. Delete this line to keep your own version.` To keep your own copy, delete that line. To turn one off, replace the file with an empty file.
